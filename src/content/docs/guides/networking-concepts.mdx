## OSI Layers

<Steps>

1. ### Physical

   The Physical layer is the literal wires and the electricity that flows through them in a network.

   The only components that operated on this layer are, as mentioned previously, wires.

   There are no protocols running on this layer, this is the initial data that is 1's and 0's (bits).

   If all you ever needed to do was send data between two computers, this is the only layer you'd need. You just hook up a cable and call it a day.

1. ### Data Link

   The Data Link layer is where networking stuff *actually* starts occuring. Here, bunches of bits get combined into one **frame** and metadata is appended to this frame with information about its source and destination.

   On the Data Link layer, hosts are described by their MAC address. This is a set of 12 hexadecimal characters given to the device by the manufacturer.

   In order to route traffic on this layer (by MAC address), we use a switch. It keeps a table of MAC Addresses, called a CAM table, and uses that to figure out where to send the frames to.

1. ### Network

   At a certain point, networks get too large for us to just use switches with really long lists of meaningless device ID's. This is where the Network layer comes in.

   At the Network layer, hosts are described by their IP address. This is a set of 4 bytes assigned to the device by a server or manually configured by a person. These addresses can be assigned, changed, and taken away at will.

   Just like the Data Link Layer, in order for data to be interpreted, a bunch of frames are gathered up into one **packet** and metadata about the source and destination IP is appended.

   Many switches these days are able to operate on the Network layer nowadays, but the quintessential router of Network layer traffic is called, well, a router.

1. ### Transport

   Finally, the last layer we are going to talk about is the Transport layer, the layer responsible for transporting data *between* networks.

   The Transport layer follows suit with the others and combines a bunch of packets into one segment/datagram. 

   The metadata applied here is the source and destination port, which is a number from 0-65535 which accompanies the IP address. We will talk more about ports later.

</Steps>

## Protocols
A protocol is just a documented way of doing something, and it means the same thing when it comes to networking. It is just a commonly used method for communicating information, and, depending on the information you're sending, you need to use a different protocol. 

### ARP

ARP stands for address Resolution Protocol, and is the protocol for obtaining the IP address for a device from its MAC address and vice versa.

The device making an ARP request just sends out a message to every other device asking "Who has this IP?" and hopes that it gets a responsible

### ICMP

ICMP is the Internet Control Message Protocol, a protocol used for the ping command. 

It operates on layer 3, sending out a small packet to a specific IP that just asks for a response

### TCP

TCP is the Transmission Control Protocol, one of two protocols that operate on the Transport layer.

TCP is a protocol that attempts to maximize reliability. It starts with what is called a three-way handshake to ensure that the source can contact the destination, and then sends over numbered segments and makes sure the receiver says that they received each packet.

This is the protocol used for websites, email, or file transfers.

### UDP

UDP is the User Datagram Protocol, and is basically TCP's exuberant twin.

UDP wants to maximize speed, so it just shoots off packets and doesn't bother to check whether the receiver received any of them.

This is the protocol used for streaming video and other protocols trying to maximize speed, like DNS and NTP.


## Internet Protocol Details

### IP Space

The complete range of IPv4 addresses is from 0.0.0.0 to 255.255.255.255, which allows for 4 BILLION unique IPs. That's a whole lot of IPs, but we also have a whole lot of things that need IPs.

BUT THERE IS A SOLUTION, (and its not IPv6 yet, because nobody wants to adopt it)

The current solution is very simple: Private and Public IP addresses

### Public IPs

Whenever devices from two different networks communicate with each other, they will always go through the networks' routers before making it to their destination. So really, if we're trying to minimize IPs, all we have to do is give them the IP of the other devices router and let the router figure out where to go from there. The IPs that the routers are assigned are called *Public* IPs.

### Private IPs

But how does the router know how to route between devices on it's network now that they don't have an IP address? Well, through a new IP address of course! This IP address only has to be unique *WITHIN* the network, so it is called an Private IP. Devices on two different networks can have the exact same Private IPs, but Public IP's are all unique.

### NAT

Now we've forced the routers to handle the tricky job of translating between public and private IP addresses (just so we're clear, routers now have both a public and private IP, each on a different connection).

The fix for this is something I've mentioned before: Ports! (I'm so great at forshadowing)

The router utilizes port numbers to decide which host in their private network to relay information to. 

### Example

That was a lot of yap, so lets give an example so you can get even more yap.

Imagine you're on your laptop visiting Google (a real fantasy world, am I right?). Your device has some private IP address such as 192.168.1.101, and your router has the private IP address 192.168.1.1. You know that Google's IP is 8.8.8.8, so you make a request from that IP. Inevitably your packet makes its way to the router, because no one in your private network has that IP. Your router converts your packet into a segment, deciding that you will be using Port 54321 for this Google visit. It sends that info to Google, along with its Public IP (we'll go with 128.123.123.123). Now when Google sends info back to 128.123.123.123, it will give the destination port of 54321, and the router will know that this data is for your laptop at 192.168.1.101!

### Private IP Ranges

There are 3 ranges of IPs that are reserved to be used only for private IP's, for the sake of not confusing the poor routers. They are:

* 192.168.0.0 - 192.168.255.255
* 172.16.0.0 - 172.31.255.255
* 10.0.0.0 - 10.255.255.255
* Bonus: 127.0.0.0 - 127.255.255.255 reserved for localhost

That is why you see these IP addresses SUPER often whenever you're doing stuff on an internal network (which is most of the time). The first value in this range is called the **Network Address** and the last value is the **Broadcast Address**. Both are reserved, meaning you can not/should not set a device to one of those IPs.

### The Whole Story

After seeing those ranges, you may be thinking (or you may not, who am I to assume) that there are some patterns in each of those IP ranges.

That is because of the secret underlying structure of IPs that I've been keeping from you this whole time..

### The Whole Story (cont.)

Because IP addresses are just sets of 4 bytes, we can rewrite any IP address in base 2 and get some nice properties. For example, the private IP ranges can be rewritten as:

* 11000000.10101000.00000000.00000000 - 11000000.10101000.11111111.11111111
* 10101100.00010000.00000000.00000000 - 10101100.00011111.11111111.11111111
* 00001010.00000000.00000000.00000000 - 00001010.11111111.11111111.11111111

Notice how the first 16, 12, and 8 bits for each of these ranges stays the same? Hmm if only there was a way to use this to create a shorthand for writing IP address ranges..

### Subnet Mask and CIDR

I have *INCREDIBLE* news, there *IS* a way to use this to create a shorthand! *Two* shorthands actually. 

The first is the **subnet mask**, a set of 4 bytes that shows the range of IPs that a device in a network can take on. The subnet mask has 1's in the places where the bits for the IP are "locked" (all IPs on the network share the exact same value for that particular bit), and 0's in the places where a device can choose either a 0 or a 1 for that bit. The 1's on the subnet mask are called the **network bits** because they define the network, and the 0's are the **host bits** because they define the host on the network.

The second is **CIDR** notation, which can be used when the subnet mask is a series of 1's followed by series of 0's. For instance, the CIDR notation for the private IP ranges are 192.168.0.0/16, 172.16.0.0/12, and 10.0.0.0/8.

### Subnetting

Now that we know how to describe IP ranges, we can divide our network up into sub-networks, subnets!

For example if you have a network with the IP range 192.168.0.0/24, and want to break it up into 2 (maybe it's your house and you want a guest and a family subnet), you can cut the range in half. 

These two ranges (192.168.0.0 - 192.168.127.255 and 192.168.128.0 - 192.168.255.255) can be represented simply as 192.168.0.0/25 and 192.168.128.0/25.

## Network Configuration

Now let's learn some actually useful information!

### Static IP Config

In order for your device to function well, you need to set up configure these things:

* IP Address: Your private IP
* Subnet Mask: The address range for your internal network
* Default Gateway: The private IP for your router
* DNS Server: The IP for your DNS server (could be either private or public)

### DHCP

But luckily, in the real world you don't even need to do that!

DHCP is the Dynamic Host Configuration Protocol, which automatically configures new devices that connect to a network.

DHCP is the reason you can just put in the WiFi password when your at someone's house, rather than do research on the structure of their internal network.

### RIP

The reason we can't reach our other network is because we haven't taught out routers how to route. There are many different protocols for this, but the one we'll be using today is by far the simplest to set up (for small networks).

It's called RIP, which stands for Routing Information Protocol, or Resting in Peace, which is what your network will be doing if you tried to use this in a large enterprise network, because it scales *TERRIBLY*

The way RIP works is that, every 30 seconds, every router broadcasts their routing table and tells the world which networks they can route to. When sending packets, routers use this info to find the path to the destination that requires the fewest "hops"

### Setting up RIP

In order to set up RIP, we need to tell the routers which networks they are directly next to. We can do this by clicking on each router, going to the "Config" tab, and clicking on "RIP"

Next we need to type in the networks that each router is directly next to (the networks they have interfaces on). For our first router, we can type in 10.0.0.0 and click "Add", and then do the same for 192.168.0.0. For router 2, we add 10.0.0.0 and 172.16.1.0
